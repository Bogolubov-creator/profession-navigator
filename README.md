# Навигатор профессий

Рабочее приложение профессионального правового справочника: поиск, вопросы гида, карточки ситуаций, пошаговые инструкции, оригиналы форм, личный план и кабинет редактора.

Полное приложение работает на Node.js 24, React и SQLite. Внешние платные сервисы не нужны. Публичное зеркало предназначено только для просмотра, поиска и скачивания разрешённых форм. Оно не содержит входа, общей базы и редакторских материалов.

## Запуск

```sh
npm ci
npm run build
npm run setup
npm start
```

Адрес: http://127.0.0.1:4317. Сервер по умолчанию слушает только локальный интерфейс. Для другого порта задайте `PORT`. Для отдельного хранилища задайте `DATA_DIR`. Пример переменных находится в `.env.example`; переменные передаются окружением, файл `.env` автоматически не загружается.

Для свежего клона без комплекта сначала выполните:

```sh
node scripts/seed-public.js
```

Будет доступен публичный каталог с файлами и настоящими локальными учётными записями. Полный редакторский архив в GitHub отсутствует намеренно.

## Вход

`npm run setup` создаёт четыре независимые локальные учётные записи: `reader`, `reader2`, `editor`, `admin`. Случайные пароли находятся в `private/credentials.json` с правами файла 0600. Откройте файл локально, скопируйте нужный пароль и нажмите «Войти». Повторный setup не меняет существующие пароли. Пароли хранятся в базе как scrypt-хеши; сессии используют HttpOnly/SameSite cookie и CSRF-токен.

Читатель сохраняет свой план и избранное. Редактор работает с материалами, версиями и источниками. Администратор дополнительно запускает импорт и управляет ролями. Выбор профессии не меняет права.

## Полный комплект и импорт

Полная локальная поставка находится в `private/handoff/`, включая HR, журналистику, архивы, альтернативные версии и референсы. Эта папка исключена из git и публичной сборки. Для переноса на другой компьютер передайте комплект отдельно по закрытому каналу и разместите его в `private/handoff/`.

```sh
npm run import -- --dry-run
npm run import
node scripts/enrich.js
```

Импорт проверяет SHA-256, допустимый тип и размер, путь и символические ссылки. Готовые вложения уже распакованы в комплекте. Произвольная загрузка/распаковка архивов через HTTP не поддерживается: такой API отсутствует. Архивы сохраняются как закрытые исходники. Повторный SHA не создаёт дубликаты и не отменяет изменения редактора. Изменение SHA создаёт предложение обновления с предыдущей суммой и новыми блоками; применение требует редакторского разбора.

Публикации, оригиналы и блоки являются разными сущностями. Все блоки имеют итог обработки; неоднозначные границы остаются в очереди проверки. `node scripts/enrich.js` дополняет первичный импорт карточками педагога и охраны труда, двумя колонками стартапера и изоляцией авторской пометки HR. Детали: CONTENT_AUDIT.md.

## Работа редактора

В кабинете доступны поиск, фильтры, страницы результатов, создание, копирование, изменение статуса, архивирование и восстановление. В редакторе находятся ситуация, адресат, сроки, два регистра ответа, ошибки, основания, шаги, важные блоки, файлы и развилки. Порядок шагов меняется кнопками; сложные развилки доступны в структурном редакторе. `index` в развилке отсчитывается с нуля. Простой просмотр JSON не считается юридической проверкой.

Сохранение использует номер версии. Конфликт не перезаписывает чужую правку и оставляет ваш текст в форме. Восстановленная версия получает статус «Требует проверки». Для юридического статуса «Проверено» нужны дата и основание. Задания, примеры и закрытые оригиналы нельзя выдавать за опубликованные ответы.

Категории, этапы, теги и чек-листы хранятся в базе. Их ID показан в списке: укажите его в форме для изменения существующей записи. Пользовательские данные, отметки прочтения, версии и сессии переживают перезапуск.

## Публичное зеркало

```sh
node scripts/release.js
npm run mirror
```

Первая команда выполняется только на полном локальном комплекте. Она один раз разрешает стартовую выборку, затем экспортирует текущее опубликованное состояние. Решения редактора по скрытию не отменяются. Вторая команда воспроизводимо строит зеркало из разрешённого `public/release/` без приватного архива. Перед коммитом обновлённой выборки проверьте её содержание и файлы.

GitHub Actions публикует `work/mirror/` через Pages при push в main. Маршруты используют hash и сохраняют поиск/номер шага после обновления. Снятие материала с локальной публикации действует на сервере сразу; для удаления старого публичного снимка нужны новый экспорт, коммит и успешная публикация Pages.

## Проверки и резервное копирование

```sh
npm test
node scripts/browser-qa.js
npm run backup -- work/backup-example
npm run restore -- work/backup-example work/restored-data
DATA_DIR=work/restored-data PORT=4320 npm start
```

Для браузерного прогона нужен установленный Playwright Chromium (`npx playwright install chromium`). `CHROME_PATH` позволяет указать имеющийся Chromium. Тесты API запускают отдельный процесс на порту 4318 и используют локальные тестовые аккаунты; запускайте на тестовой копии базы при наличии реальных пользовательских данных.

Копия создаётся через SQLite VACUUM INTO, включает весь комплект и реестр SHA-256. Восстановление допускается только в новый каталог, проверяет суммы и целостность SQLite. Файл с исходными паролями не копируется; сохраните его отдельно в защищённом месте. Восстановление базы сохраняет хеши паролей.

## Эксплуатационные границы

Один сервер и локальный диск SQLite. Для интернет-размещения нужны HTTPS, `COOKIE_SECURE=1`, постоянный диск, защищённое резервирование и отдельная проверка инфраструктуры. Docker и серверный HTTPS-хостинг в этой поставке не проверялись. Статическое зеркало не является серверным развёртыванием.

Правовая актуальность импортированных текстов не подтверждена. В источниках есть пробелы, редакторские задачи и неоднозначная PDF-вёрстка. Сведения о проверках и ограничениях находятся в QA_REPORT.md и CONTENT_AUDIT.md. Отправка внешних уведомлений, mos.ru, LLM-консультант и платежи в продукт не входят.
